# Review проекта DailyPlanner — 2026-08-19

## Итог

Рабочий небольшой продукт с хорошей предметной моделью и тестовой базой. Главный риск — не функциональность, а надёжность единственного 24/7-процесса с напоминаниями и внешними AI-сервисами.

## P0 — до следующего production-релиза

- [x] Добавить CI: lint, typecheck, тесты, проверка Alembic single-head и сборка deployment-артефактов.
- [x] Сделать автоматический restore drill для PostgreSQL-backup и документировать фактические RPO/RTO; одного создания архива недостаточно.
- [x] Ввести singleton/leader lock для scheduler и тест, доказывающий отсутствие двойных напоминаний при двух экземплярах.
- [x] Покрыть crash/restart-сценарии: write-ahead сообщения, sweep пропущенных задач, graceful shutdown и повторная доставка без дублей.
- [x] Проверить `.env`, Telegram session и резервные копии на отсутствие в Git; добавить автоматический secret scan.

## P1 — ближайший цикл

- [x] Перейти с одного `requirements.txt` на `pyproject.toml` и воспроизводимый lockfile; отделить runtime/dev зависимости.
- [x] Добавить метрики SLO: задержка напоминаний, размер очередей, ошибки LLM/STT, возраст последнего backup, длительность scheduler jobs.
- [x] Создать контрактные тесты для LLM JSON/function calls и набор regression fixtures для русских дат, часовых поясов и повторяющихся задач.
- [x] Проверить конкурентные изменения одной задачи и ввести optimistic/version guard там, где возможна потеря обновления.
- [x] Устранить расхождения macOS/VPS запусков: одинаковые health/readiness проверки и единый release checklist.

## P2 — после стабилизации

- [x] Ввести небольшую архитектурную карту границ `handlers → services → repositories`, чтобы логика не расползалась по Telegram handlers.
- [x] Добавить измеримую оценку качества LLM: intent accuracy, invalid-tool rate, fallback rate и набор обезличенных golden cases.
- [x] Описать удаление пользовательских данных, сроки хранения LLM-логов и embeddings.

## Definition of Done

- CI зелёный на чистом checkout; backup реально восстановлен в изолированную БД.
- Два параллельных экземпляра не создают двойную доставку.
- Есть dashboard/alert на пропущенное напоминание и просроченный backup.
- Release и rollback воспроизводимы по одному runbook без ручных догадок.
