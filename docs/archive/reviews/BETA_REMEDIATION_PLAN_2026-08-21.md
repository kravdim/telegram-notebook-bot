# План исправлений по итогам бета-теста 20–21.08.2026

Источник: [BETA_TEST_2026-08-20.md](BETA_TEST_2026-08-20.md).

## Цель

Устранить подтверждённые ошибки живого Telegram E2E-теста, закрепить поведение
автоматическими тестами и повторно проверить production-сценарии юзерботом.

## Этап 1 — P0: целостность пользовательских действий

- [x] Расширить защиту от ложных подтверждений на дни рождения, заметки,
  напоминания и проекты.
- [x] При mutate-intent без корректного tool call выполнить один retry с
  `tool_choice=required`.
- [x] Fail closed: если retry снова не вернул изменяющий tool, ничего не менять
  и явно сообщить пользователю.
- [x] Добавить golden-cases для дня рождения, относительного напоминания и
  повторяющейся задачи.
- [x] Сократить TTL ожидания мемуарника с 12 часов до 60 минут.
- [x] Не направлять командоподобный текст в мемуарник без явного reply.
- [x] Добавить кнопку «Пропустить» с очисткой persistent state.
- [x] Перенести загрузку локальной Whisper-модели на этап установки, включить
  offline runtime, прогрев при старте, пользовательский статус и таймаут.

## Этап 2 — P1: корректная маршрутизация и эксплуатация

- [x] Закрепить в tool schema и активном DB-промпте правило: повторяющееся
  действие — `create_task`, `create_reminder` — только по явному «напомни».
- [x] Добавить пример «через N минут» и обязательную нормализацию в ISO datetime.
- [x] Удалить второе итоговое сообщение после декомпозиции слона.
- [x] Преобразовать `TelegramConflictError` в метрику и throttled alert админу.
- [x] Убедиться, что на известных хостах фактически работает один poller.

## Этап 3 — P2: UX

- [x] Валидировать имя онбординга: 1–3 слова, буквы/дефис/апостроф, до 50 знаков.
- [x] При `/start` повторно показывать текущий шаг незавершённого онбординга.
- [x] В `/notes` показывать заголовок и содержимое заметки.
- [x] Не считать любую «встречу» признаком ценности «дружба».

## Этап 4 — проверка и выпуск

- [x] Unit/regression suite.
- [x] LLM contract fixture gate.
- [x] Alembic single-head и миграция активного intent-промпта.
- [x] PostgreSQL integration + backup/restore drill на одноразовой БД.
- [x] Целевой production E2E-регресс исправленных сценариев юзерботом.
- [x] После зелёного целевого E2E отметить исправления в исходном
  бета-отчёте выполненными.

Полный 35-минутный прогон всех исторических кейсов остаётся отдельным ручным
release-gate: он включает уже проверенные сценарии и состояние онбординга
тестового аккаунта. Для этого релиза выполнен целевой прогон 10 затронутых
кейсов (8/10; B3 исправлен и повторно прошёл, G3 фактически выполнил snooze,
а неточная формулировка подтверждения исправлена и покрыта тестом).

## Критерии готовности

- Ни одно изменение данных не подтверждается без успешного mutating tool call.
- Команда не попадает в мемуарник только из-за старого вечернего состояния.
- Голосовой сценарий отвечает сразу и ограничен таймаутом.
- Повторяющаяся привычка видна в задачах и может быть выполнена.
- В логах нет устойчивого `TelegramConflictError`.
- Unit, integration, migration, restore и живой E2E проходят без регрессий.
