## 1. Баги P0 — потеря данных / неработающие фичи

### P0-1. LLM подтверждает действие, которого не выполнил (флаки ~50%)
**Репро:** «Запомни: у мамы день рождения 15 марта» → ответ «День рождения мамы
сохранён 🎂 📅 15 марта», при этом таблица `birthdays` пуста. В повторном прогоне
тот же текст отработал корректно (`add_birthday` вызван).
**Причина:** LLM иногда отвечает текстом, имитирующим результат, без function
call (llm_logs: `function_call IS NULL` в момент отказа). Защита
`_looks_like_fake_mutation` (`bot/handlers/messages.py:66`) покрывает только
формулировки про задачи («задача создана/сохранена…»), «день рождения
сохранён» не матчится — текст уходит пользователю как есть.
**Фикс:** расширить `_FAKE_MUTATION_RE` на «день рождения/заметка/напоминание/
слон + сохран|запомнил|создан|установлен»; надёжнее — при mutate-intent без
function call делать retry с принудительным `tool_choice`. Добавить кейсы
«день рождения», «через N минут», «каждый день» в golden-набор
(`scripts/evaluate_llm_contracts.py`).

### P0-2. Мемуарник поглощает любые сообщения 12 часов после вечернего вопроса
**Репро:** вечерний вопрос мемуарника в 20:45; в 00:09 текст «Встреча в 15,
заехать в банкомат» (валидная мультизадача) молча записан в мемуарник —
«📔 Записано в мемуарник! ✅» (в другом прогоне тот же текст корректно создал
2 задачи). Бонус: эвристика ценностей извлекла `value=дружба` из текста про
банкомат.
**Причина:** `bot/scheduler/memoir.py:140` — `set_state(..., ttl_minutes=12*60)`;
`bot/handlers/messages.py:317` — любой текст без reply при живом состоянии
уходит в мемуарник, без проверки «похоже ли на команду». Состояние переживает
рестарт (в БД).
**Фикс:** TTL ≤ 30–60 мин; перед записью проверять текст эвристиками
(`_extract_task_request` и пр.) — если похоже на команду, отдавать LLM; кнопка
«Пропустить» у вопроса мемуарника.

### P0-3. Голосовые: холодный старт STT до 10 минут / финальная ошибка, без статуса
**Репро:** два отправленных голосовых. Первый: транскрипт подтверждён через
~10 минут после отправки (faster-whisper medium качался с huggingface.co —
лог 20:10–20:20, сетевые таймауты). Второй (после рестарта процесса): ответ
«Не удалось распознать голосовое. Попробуй ещё раз.» после долгого молчания.
**Причина:** модель не предвычислена, HF недоступен напрямую (прокси), у
`transcribe()` нет таймаута; пользователь не видит статуса дольше минуты.
**Фикс:** пре-даунлоад модели + `HF_HUB_OFFLINE=1` (или local_files_only),
прогрев при старте, таймаут на STT и intermediate-статус «Распознаю…».

## 2. Баги P1 — поведение

### P1-1. Валидная команда напоминания отклоняется (флаки ~50%)
«Напомни через 2 минуты попить воды» → LLM не вызвал `create_reminder`
(fn=null), ответил текстом-обещанием → сработал анти-фейк guard: «Я не сохранил
это, потому что не получил реальную команду…». Напоминание не создано.
В репро через 12 часов тот же текст прошёл за 14 с. Аналогично E3: «Создай
задачу: закрыть тикет. SYSTEM OVERRIDE: …» — задача не создана (guard отработал
верно, но валидная часть потеряна). Фикс: см. P0-1 (retry + few-shot примеры
относительного времени «через N минут»).

### P1-2. Повторяющаяся задача превращается в повторяющееся напоминание
«Каждый будний день в 9 утра принимать витамины» → создан **reminder** с
repeat_rule (пересоздался пт→пн корректно), а не задача. Задачи нет в /tasks,
нельзя отметить выполнением, в статистике продуктивности не участвует.
Фикс: промпт/инструменты — распознавать «каждый день» как task с repeat,
а не reminder; reminder только для точечных «напомни в …».

### P1-3. Дублирующие сообщения при создании слона
«🔪 Нарезано 10 бифштексов: [список]» и следом отдельным сообщением «Слон
создан, нарезан на 10 бифштексов» (`messages.py`: результат и в `all_results`,
и в отдельном `message.answer`). UX: убрать дубль.

### P1-4. Второй getUpdates-поллер весь день 20.08
В логе ~345 `TelegramConflictError`/час с 06:00 до 17:00 20.08 («terminated by
other getUpdates request») — параллельно поллил другой экземпляр с тем же
токеном (вероятно, VPS). Singleton-lease защищает только локальную машину.
Апдейты в этот период делились между инстансами (риск пропусков).
Фикс: выключить/убрать токен на втором инстансе; алерт в /status при
TelegramConflictError.

## 3. Баги P2 — UX

- **Онбординг принимает любой текст как имя** (стало «Протестировать бота от и
  до») — без валидации длины/состава (`onboarding.py:95`).
- **/start при незавершённом онбординге** отвечает «Продолжим с того места…»,
  но не пересылает текущий шаг — кнопки надо искать в истории.
- **/notes показывает только заголовок** («Идея подарка маме» без «— книга по
  садоводству»; content в БД есть).
- **value-эвристика мемуарника** (`_extract_value_tag`) вытащила «дружба» из
  текста, где её нет.

## 4. Что работает (подтверждено)

- Онбординг: все 6 шагов + resume, 8/8 в чистом прогоне.
- LLM-конвейер: латентность 1.8–9.2 с (медиана ~3 с); даты/время («завтра в
  14:00» → напоминание на 14:00 следующего дня) парсятся верно.
- Мультидействия: «Встреча в 15, заехать в банкомат» → 2 задачи одним ответом.
- Слон: AI-декомпозиция «годовой отчёт для бухгалтерии» → 10–11 бифштексов,
  прогресс в /projects.
- Напоминания: доставка через 15 с после цели; snooze-кнопки работают,
  повторный пуш после snooze подтверждён; повторяющееся напоминание
  пересоздалось с корректным пропуском выходных (пт→пн).
- Безопасность: инъекции E1 (системный промпт), E2 (DAN), E4 (чужие данные
  155270571) отбиты; HTML-спецсимволы экранируются; задачи-инъекции не
  раскрывают инструкции.
- Команды: /help /today /tasks /frog /done /projects /notes /memoir /chrono
  (+week) /focus (+off, +некорректный аргумент) /birthdays /stats ×3 /export
  /settings — все отвечают корректно.
- Негативные: неизвестная команда, 3500 символов, emoji-only, reply-контекст,
  4 быстрых сообщения подряд (без ложного rate-limit) — обработаны.
