# Исправления по ревью 7 сентября 2026

Подтверждённые дефекты **R01–R33 исправлены в рабочей копии**. Полный локальный
прогон: **700 passed, 1 skipped**, покрытие **74,79%**; критические пороги покрытия
сохранены. Новая миграция: `e0a3b5c7d914`.

Основание: [комплексное ревью](REVIEW_2026-09-07_COMPREHENSIVE.md).
Исходный commit: `b845c087fa9046478138efa737a9d1469f0c0835`, версия 0.5.0.
Изменения находятся в **Unreleased**, новый релиз/тег не публиковался.
Это отчёт о локально проверенной рабочей копии, а не о production-развёртывании.
Исторические отчёты и их прежние результаты не считаются проверкой этих изменений.

## Исправления

| Ревью | Реализованное поведение |
| --- | --- |
| R01 | Потоковый backup читает блоками по 64 KiB, поддерживает длинные COPY-строки. Фильтр несовместимого SQL-параметра действует только в преамбуле и не удаляет совпадающий пользовательский текст внутри COPY. |
| R02 | Ротация выполняется после успешного backup. Ошибка не удаляет предыдущую копию; последняя точка восстановления сохраняется даже после превышения срока хранения. |
| R03 | Watcher проверяет владение advisory lock на исходном PostgreSQL-соединении. Потеря соединения/lock останавливает polling и readiness, затем освобождаются ресурсы runtime. |
| R04 | Закрытие проекта отменяет открытые задачи через общий lifecycle, закрывает связанные напоминания и очищает их lease. Создание задач закрытого или чужого проекта запрещено. |
| R05 | Backup, reindex и retention — независимые фоновые задачи. Медленный индексатор не задерживает backup и очистку. |
| R06 | В Linux Compose разделены bootstrap, migration и application роли. Роль бота без SUPERUSER/CREATEDB/CREATEROLE/BYPASSRLS и без CREATE в public; миграции выполняет отдельный одноразовый сервис. |
| R07 | Глобальные команды доступны во время регистрации. Обработчики текстовых шагов onboarding исключают slash-команды. Добавлен `/cancel`. |
| R08 | FSM использует атомарные upsert отдельных полей и JSONB merge; `SimpleEventIsolation` сериализует события одного FSM-ключа. |
| R09 | Завершение профиля и первая задача сохраняются одной транзакцией. Повторный callback/запрос не создаёт ещё одну задачу; название ограничено 500 символами, вывод без интерпретации HTML. |
| R10 | Длинная расшифровка показывается безопасными частями, кнопки прикреплены к последнему сообщению. Ошибки UI подтверждения не оставляют невосстановимый переход перед выполнением команды. |
| R11 | Временное аудио удаляется в `finally`, включая ошибку скачивания и отмену запроса. |
| R12 | Локальный STT использует отдельный исполнитель с одним native worker. Timeout не освобождает слот, пока native-работа не закончилась; выгрузка модели стоит после неё. Ограничение принудительной остановки описано ниже. |
| R13 | Все таблицы и счётчики export читаются из одного repeatable-read/read-only снимка. Сжатие ZIP вынесено из event loop, разрешён один export одновременно. Отмена дожидается файлового writer перед cleanup. |
| R14 | Независимый outbox worker продолжает сохранённые части вне исходного scheduler-окна; есть backoff, максимум 8 попыток, постоянные ошибки и срок годности. |
| R15 | Каждая попытка внешнего LLM-запроса заново проверяет согласие в свежей DB-сессии непосредственно перед egress, включая запрос, ожидавший в очереди. |
| R16 | Повторяющаяся задача хранит `recurrence_timezone`; изменение профиля не сдвигает существующую серию. Timezone фиксируется и при включении повторения у существующей задачи. |
| R17 | Отсутствие успешного backup больше не считается нормальным состоянием SLO. |
| R18 | Настроенные интервалы healthcheck/sweep применяются. Интервалы и сроки хранения проверяются как положительные целые числа, включая transient state retention. |
| R19 | Вектор имеет fingerprint провайдера, модели, размерности, endpoint и формата текста. Векторы неизвестной/иной версии не участвуют в semantic ranking; текстовый поиск продолжает работать до переиндексации. |
| R20 | `/retry` показывает страницы по 5 запросов, узнаваемые фрагменты действий и подтверждаемое закрытие продолжения. Уже совершённые действия при закрытии не удаляются. |
| R21 | Gitleaks подключает стандартный набор правил; отсутствуют исключения для целых файлов документации и `.env.example`. Проверено настоящим сканером и двумя canary-токенами. |
| R22 | Обновление списка доступа сохраняет symlink общего конфигурационного файла между релизами. При env override запрещён ложный отчёт о персистентной смене файлового списка доступа. |
| R23 | Migration head определяется относительно выбранного релиза, независимо от cwd. Совместимый rollback требует явного контракта startup; иначе installer останавливается до миграции и требует maintenance-переход. |
| R24 | Вечерние callback выполняют переход только из ожидаемого `open`; старые кнопки не перезаписывают историю завершения задачи. |
| R25 | Недельные/месячные обзоры используют реальные календарные границы, исключают записи предыдущего периода и будущие записи; статистика учитывает timezone пользователя. |
| R26 | `title: null` отклоняется вместо сохранения строки `None`. |
| R27 | Следующий экземпляр серии сохраняет разницу между плановой датой и дедлайном. |
| R28 | Изменение мемуарной записи сбрасывает старый embedding. Поздний reindex сохраняет вектор только при совпадении исходного текста/названия с текущими данными. |
| R29 | Часовой список задач использует outbox; legacy-маркер выставляется после полной доставки. Срок годности сообщения ограничен концом часа. |
| R30 | Относительный отступ создаёт настоящее связанное напоминание; сохраняется при обновлении дубля. Несогласованное абсолютное время и отступ отклоняются. |
| R31 | Restore включает `pipefail` и проверяет gzip до обращения к psql. Повреждённый архив с корректной checksum не выдаётся за успешно восстановленный. |
| R32 | Для 29 февраля применяется единая политика: 28 февраля в невисокосный год; неизвестный год представлен високосным 2000, включая совместимость со старым sentinel. |
| R33 | Marker-ветка E2E cleanup ограничена владельцем FSM, а не только совпадением marker. |

Во время совместного прогона дополнительно исправлена смена «лягушки»:
снятие прежнего флага принудительно flush-ится до установки нового. Это устраняет
зависимость от порядка UPDATE в ORM и нарушение уникального индекса PostgreSQL.
Во время первого production maintenance-перехода дополнительно обнаружено, что
launchd после успешного `bootout` кратко продолжает показывать завершающийся job.
Контроллер теперь ограниченно ждёт точный service-not-found; другие ошибки остаются
fail-closed. Попытка остановилась до snapshot/миграции, прежний runtime был возвращён.

## Условия выпуска и пределы гарантий

1. Перенос существующего Docker volume на разделённые роли выполняется по
   [Operations](OPERATIONS.md), с проверенной копией и maintenance-окном.
   Init-скрипты не меняют уже существующий кластер. Пароли трёх ролей должны отличаться.
2. Новая схема не объявлена совместимой с автоматическим rollback старого runtime.
   Downgrade теряет новые metadata, включая точное значение failed/expired outbox;
   для сохранения смысла прежних данных используется pre-upgrade snapshot.
3. Telegram не предоставляет идемпотентный send: crash после принятой отправки до
   commit может привести к повтору. Outbox гарантирует сохранение прогресса и
   ограниченное продолжение, но не exactly-once delivery на сетевой границе.
4. Timeout native Whisper ограничивает принятие следующей работы; без кооперации
   библиотеки безопасно прервать уже выполняющийся native вызов нельзя.
5. Для защиты от потери диска/хоста нужна выбранная владельцем off-host копия,
   шифрование и проверка восстановления скачанного архива. Локальный RTO не
   доказывает достижение удалённого RPO/RTO.
6. Перед выпуском нужен CI этой ревизии и контролируемая live-проверка на тестовом
   Telegram-профиле. Production не перезапускался, сообщения не отправлялись.
