# Этап 3. Задачи + Лягушка

## Цель
Полноценная работа с задачами: создание, редактирование, удаление, приоритеты, лягушка, напоминания с snooze.

## Задачи
- crud/tasks.py: create, get_by_id, get_open(user_id), get_today(user_id), update, delete, set_frog, complete
- crud/reminders.py: create, get_pending, mark_sent, snooze(+30min, +1h, tomorrow_morning)
- Команда /tasks — список открытых задач (с эмодзи приоритетов и 🐸 для лягушки)
- Команда /frog — показать текущую лягушку или предложить назначить
- Команда /done [название] — fuzzy-поиск по title, отметить выполненной
- Confirm-кнопки для удаления: "Нашёл задачу X. Удалить? [🗑 Да] [❌ Отмена]"
- Snooze inline-кнопки на напоминаниях: [⏰ +30 мин] [⏰ +1 час] [📅 Завтра утром] [✅ Сделано]
- snooze_count <= 5, после — "Это напоминание уже откладывалось 5 раз"
- Двойной контур: scheduler/sweep.py — каждые 5 мин проверяет remind_at < now() AND is_sent = false
- scheduler/reminders.py — APScheduler job для отправки напоминаний (основной контур)

## Проверка
- [ ] Создание задачи голосом и текстом
- [ ] /frog назначает лягушку
- [ ] Напоминания приходят вовремя (±1 мин)
- [ ] Snooze работает (все варианты)
- [ ] Sweep подбирает пропущенные напоминания
- [ ] Confirm перед удалением

# Этап 4. Дайджесты

## Цель
Утренний и вечерний дайджесты с полной структурой. Вечерний разбор невыполненных задач.

## Задачи
- scheduler/digest.py: персональные APScheduler jobs для каждого пользователя
- formatters/digest.py: форматирование утреннего дайджеста (🐸 лягушка → 🔴 срочные → 📅 расписание → 🐘 бифштексы → 🕐 гибкие → 📌 просроченные + нераспределённые с вчера)
- Адаптация для выходных: без лягушки (опционально), без хронометража, только личное + напоминания
- Вечерний итог: ✅ выполнено → 🐸 статус → ⏳ невыполненные
- formatters/evening_review.py + handlers/evening_review.py:
  - Для каждой невыполненной задачи inline-кнопки: [📅 Завтра] [📆 На дату] [❌ Снять] [⬇️ Понизить]
  - Кнопка [➡️ Все на завтра] для массового переноса (если 3+ задач)
  - При "На дату" — бот спрашивает дату, предлагает варианты: послезавтра, понедельник, конец недели
  - Если не разобрал — автоперенос на завтра, утром уведомление
- Идемпотентность: digest_sent_date, memoir_asked_date

## Проверка
- [ ] Утренний дайджест в настроенное время с правильной структурой
- [ ] Вечерний итог с разбором невыполненных
- [ ] "Все на завтра" переносит все задачи
- [ ] В выходные — адаптированный формат
- [ ] Перезапуск бота не дублирует дайджест (идемпотентность)

# Этап 6. Мемуарник

## Цель
Ежедневная фиксация ГСД, извлечение ценностей, недельный/месячный ревью.

## Задачи
- scheduler/memoir.py: вопрос в memoir_prompt_time пользователя
  - Отправить: "📔 Время мемуарника. Какое событие сегодня было самым ярким?"
  - Идемпотентность: memoir_asked_date
  - Если не ответил за 2 часа — не повторять
  - Grace period 24 часа: ответ на следующий день привязывается к вчера
- handlers/: обработка ответа на мемуарник
  - Определить что это ответ мемуарника (по контексту: был ли задан вопрос за последние 24 часа)
  - Сохранить в memoir_entries
  - LLM извлекает value_tag (prompt_key: memoir_value_extraction)
  - Ответ: "Записала! Похоже, сегодня для тебя важна {value_tag} 💛"
- Недельный ревью (воскресенье вечером):
  - Показать 7 ГСД с номерами
  - Inline-кнопки с номерами + [Написать своё]
  - Сохранить с period_type='week'
- Месячный ревью (последний день месяца) — аналогично
- Команда /memoir — последние 7 ГСД + статистика ценностей
- Команда /memoir week, /memoir month

## Проверка
- [ ] Вопрос мемуарника приходит вовремя
- [ ] Ответ сохраняется с правильной датой
- [ ] Grace period 24 часа работает
- [ ] Недельный ревью с inline-кнопками
- [ ] /memoir показывает записи и статистику

# Этап 7. Хронометраж

## Цель
Периодический опрос с AI-реакциями, адаптивная частота, режим фокуса, фотография дня.

## Задачи
- scheduler/chronometry.py: персональный job для каждого пользователя с chronometry_enabled=true
  - Проверки перед отправкой: рабочий день? рабочие часы? фокус не активен? нет активной встречи?
  - Вариации вопросов от LLM (не одинаковые каждый раз)
  - Inline-кнопки: [Работаю по плану] [Перерыв] [Встреча] [🎯 Фокус 2ч]
- handlers/chronometry.py: обработка ответов
  - Текст или кнопка → LLM (prompt_key: chronometry_reaction) → category, productivity_score, reaction
  - Сохранить в time_tracking_entries
  - Отправить реакцию пользователю
- Адаптивная частота:
  - Первая неделя: 60 мин. Вторая: 30. Далее: пользователь настраивает
  - Если 3 пропуска подряд — увеличить интервал, спросить: "Сделать паузу до конца дня?"
- Режим фокуса:
  - /focus [N] — установить focus_until = now() + N минут
  - Inline-кнопка "🎯 Фокус 2ч" на сообщении хронометража
  - Хронометраж приостановлен, напоминания доставляются
  - По окончании: "Фокус-сессия завершена. Как продвинулось?"
  - В time_tracking_entries: category='focus', duration_minutes=N
- Умная пауза при встречах:
  - Если due_time задачи наступило и задача выглядит как встреча → одно сообщение + кнопка [Ещё идёт]
- formatters/chronometry.py: фотография рабочего дня
  - Агрегация time_tracking_entries за день по category
  - 🟢 Продуктивная: X ч Y мин (N%) / 🎯 Фокус: ... / 🔵 Нейтральное: ... / 🔴 Потери: ...
- Команда /chrono — фотография за сегодня/указанную дату
- Команда /chrono week — за неделю
- Поведение в выходные и нерабочее время: хронометраж НЕ работает

## Проверка
- [ ] Опрос приходит каждые N минут в рабочее время
- [ ] LLM-реакции разнообразные и уместные
- [ ] /focus останавливает хронометраж на заданное время
- [ ] Inline-кнопка "Фокус 2ч" работает
- [ ] Адаптивная частота: увеличение при игнорировании
- [ ] Фотография дня в вечернем итоге
- [ ] В выходные и после work_end — тишина

# Этап 9. Заметки + RAG

## Цель
CRUD заметок и дневника, семантический поиск, гибридный поиск.

## Задачи
- crud/notes.py, crud/diary.py
- embeddings/indexer.py: фоновая индексация
  - Metadata-обогащение: "[дата] [категория] [теги] текст" → embedding
  - Оригинал без изменений в БД
  - Чанкинг: < 300 слов — один вектор, > 300 — рекурсивный сплит (400-500 токенов, 10-15% overlap)
- Гибридный поиск:
  - pgvector cosine similarity + pg_trgm similarity
  - RRF: 0.6 × semantic_rank + 0.4 × text_rank
  - Top-5 результатов
- Function call "search" — поиск по всем сущностям
- Команда /notes — последние 10 заметок
- scheduler/reindex.py — повтор индексации для записей с NULL embedding

## Проверка
- [ ] "Найди заметку про клиента Петра" — находит через семантический поиск
- [ ] Длинные записи чанкируются корректно
- [ ] Reindex подбирает записи с NULL embedding
